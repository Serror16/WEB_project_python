# Документация проекта: Унифицированный налоговый шлюз (Django)

Данный проект представляет собой REST API шлюз, разработанный на базе фреймворка Django и Django REST Framework (DRF). Проект разделен на логические приложения (apps) для обработки аутентификации, налоговых запросов и управления пользователями.

## 1. Запуск проекта локально

Для локального запуска необходимо подготовить виртуальное окружение, применить миграции к базе данных и запустить встроенный сервер разработки.

### Шаг 1: Подготовка окружения

Перейдите в корневую папку проекта и создайте виртуальное окружение:

```
python -m venv venv
# Для Windows:
.\venv\Scripts\activate
# Для Mac/Linux:
source venv/bin/activate

```

Установите все необходимые зависимости из файла `requirements.txt`. Файл с зависимостями находится внутри исходного кода проекта:

```
cd src/main
pip install -r requirements.txt

```

### Шаг 2: Настройка переменных окружения

В папке `src/main/` (рядом с файлом `manage.py`) создайте файл `.env`. Заполните его базовыми настройками (секретный ключ и параметры базы данных), чтобы проект мог успешно запуститься.

```
DJANGO_KEY=django-insecure-your-secret-key
DATABASE_ENGINE=django.db.backends.sqlite3
DATABASE_NAME=db.sqlite3

```

### Шаг 3: Применение миграций

Для создания необходимых таблиц в базе данных (включая таблицы для аудит-лога и авторизации) выполните команды инициализации миграций:

```
python manage.py makemigrations
python manage.py migrate

```

### Шаг 4: Запуск сервера

Запустите локальный сервер разработки Django:

```
python manage.py runserver 8000

```

API будет доступно по адресу `[http://127.0.0.1:8000](http://127.0.0.1:8000)`.

## 2. Архитектура и структура проекта

Проект базируется на классической структуре Django, где логика разделена по приложениям (находящимся в `src/main/`):

* **`tax_gateway`** — основное ядро, обрабатывающее налоговые отчеты.


* **`my_auth`** — логика аутентификации, генерации и валидации JWT-токенов.


* **`users`** — управление моделями пользователей.


* **`config`** — общие настройки проекта, маршрутизация и конфигурации баз данных.



Логика обработки налогового запроса построена на следующих слоях:

### Слой маршрутизации и валидации (API Layer)

* **Файлы:** `tax_gateway/views.py` и `tax_gateway/serializers.py`.


* **Ответственность:**
* Маршруты (URLs) направляют запросы в классы-представления (Views) внутри `views.py`.


* Сериализаторы из `serializers.py` отвечают за строгую валидацию входящего JSON-тела (например, проверка типов данных, обязательных полей).


* В случае невалидных данных генерируется ошибка структуры, если данные корректны — они передаются дальше.



### Слой аудит-логирования (Middleware)

* **Файлы:** `tax_gateway/middleware.py`.


* **Ответственность:**
* Перехватывает каждый входящий запрос и исходящий ответ (глобально, на уровне всего приложения).


* Измеряет время обработки запроса и сохраняет тела (payloads) запросов и ответов в базу данных для соответствия требованиям аудита.



### Слой хранения данных (Models Layer)

* **Файлы:** `tax_gateway/models.py`, `my_auth/models.py`.


* **Ответственность:**
* Описывает структуру базы данных (ORM).


* Обеспечивает сохранение аудит-логов и налоговых статусов.



### Слой адаптеров (Adapter Layer)

* **Файлы:** `tax_gateway/adapters.py`.


* **Ответственность:**
* Инкапсулирует логику отправки данных во внешние налоговые сервисы разных юрисдикций.


* Преобразует JSON-данные из сериализатора в необходимый формат (например, XML) перед отправкой внешнему провайдеру.


* Обрабатывает ошибки внешних API и реализует механизмы повторных попыток.
