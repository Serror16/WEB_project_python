# Документация проекта: Унифицированный налоговый шлюз (Flask)

Данный проект представляет собой REST API-шлюз (на базе Flask) для интеграции с различными внешними налоговыми сервисами. Проект построен с применением принципов чистой архитектуры.

## 1. Запуск проекта локально

Все компоненты системы необходимо поднять в локальном окружении Python.

### Шаг 1: Подготовка окружения

Убедитесь, что у вас установлен Python 3.11+. Создайте и активируйте виртуальное окружение в корне проекта:

```
python -m venv venv
# Для Windows:
.\venv\Scripts\activate
# Для Mac/Linux:
source venv/bin/activate

```

Установите все необходимые зависимости из файла:

```
pip install -r requirements.txt

```

### Шаг 2: Инициализация базы данных

Перед запуском основного приложения необходимо создать таблицы в базе данных. В корне проекта выполните скрипт:

```
python create_tables.py

```

### Шаг 3: Запуск Mock-серверов (Внешние сервисы)

Для эмуляции работы реальных налоговых систем в корне проекта предусмотрены заглушки. Их нужно запустить в отдельных терминалах (с активированным виртуальным окружением):

```
# Терминал 1:
python mock_tax_server.py

# Терминал 2:
python mock_usa_server.py

```

### Шаг 4: Запуск основного API Gateway

В новом терминале запустите приложение Flask. Точка входа находится в корне проекта:

```
python run.py

```

После запуска документация Swagger (Flasgger) будет доступна по адресу: `[http://127.0.0.1:5000/apidocs/](http://127.0.0.1:5000/apidocs/)`.

## 2. Архитектура и структура проекта

Проект использует многослойную архитектуру. Общая логика обработки запроса выглядит следующим образом:
`Client -> API -> Service -> Adapter`.

### Клиент (Client)

* **Действие:** Отправляет `POST /api/v1/tax/report?country=russia` с JSON-телом.
* **Источник:** Внешний сервис, Postman или Swagger.

### Слой маршрутизации (API Layer)

* **Файлы:** `app/api/v1/endpoints/tax.py` и `app/schemas/tax.py`.
* **Ответственность:**
* **Маршрутизация:** Flask принимает запрос через `Blueprint` и извлекает сырой JSON с помощью `request.get_json()`.
* **Ручная валидация:** В отличие от старой реализации, валидация не происходит автоматически. Данные вручную передаются в схему валидации `Pydantic`/`Marshmallow` в `schemas/tax.py`.
* **Обработка ошибок:** Если данные невалидны (например, отрицательная сумма), API перехватывает ошибку валидации и вручную возвращает `400 Bad Request`.
* **Оркестрация:** Если всё ок, контроллер в `endpoints/tax.py` просто вызывает метод сервиса: `tax_service.send_report(data)`.

### Слой бизнес-логики (Service Layer)

* **Файлы:** `app/services/tax_service.py`.
* **Ответственность:**
* **Маршрутизация:** Сервис смотрит на параметр `country` и решает, какой адаптер нужно вызвать.
* **Отказоустойчивость:** Здесь находится Retry-логика. Если адаптер упал, сервис пробует повторить запрос.
* **Идемпотентность:** Проверяется `idempotency-key`, чтобы избежать двойной отправки одного и того же отчета.
* **Логирование:** Вызывает модели из `app/db/models.py`, чтобы сохранить факт запроса в базу данных.


### Слой адаптеров (Adapter Layer)

* **Файлы:** Адаптеры лежат в `app/adapters/` (например, `russia_adapter.py`).
* **Ответственность:**
* **Трансформация:** Конвертирует чистый JSON в формат, который понимает конкретная внешняя налоговая система (например, в XML с помощью `app/utils/xml_parser.py`).
* **Специфика интеграции:** Добавляет нужные заголовки аутентификации или SOAP-обертки.
* **Инкапсуляция ошибок:** Если внешняя налоговая возвращает непонятную ошибку, адаптер перехватывает её и трансформирует в унифицированную модель ошибки, описанную в `app/schemas/errors.py`.


### Внешние сервисы (External Service)

* **Суть:** В проекте используются скрипты-заглушки (mocks).
* **Ответственность:** Имитируют работу реальной налоговой. Один мок отвечает быстро по REST, другой — медленно по SOAP, а третий специально выдает ошибку, чтобы можно было протестировать работу Retry-логики в сервисе.
